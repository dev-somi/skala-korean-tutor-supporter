# ADR-0031: 학생마다 학습 계획(목표·경로·속도)을 두고, 수업 기록의 이해도로 "천천히 / 빨리 / 계획 다시 보기"를 제안한다
- 상태: Accepted (2026-10-21) — 구현은 단원 시트의 "책 + 과" 전환([ADR-0030](0030-unit-sheets-from-materials.md) 다음 단계) 뒤에 한다
- 관련 모듈: 학생 관리, 수업 준비(다음 과 정하기), 수업 후 기록(승인 화면의 "다음에 배울 과"), 수업 준비 탭 카드
- 기술 설계: (구현할 때 기술 ADR을 쓴다)
- 관련 ADR: [ADR-0016](0016-persona-anchor-textbook-standard-levels.md) (중심 교재 순서를 따른다), [ADR-0029](0029-understanding-from-transcript-drives-review.md) (항목별 이해도), [ADR-0030](0030-unit-sheets-from-materials.md) (단원 시트, 표준 ID 진도), [ADR-0009](0009-hitl-on-all-writes.md)

## 배경 (Context)
- 실제로 가르칠 때는 수업 전에 **목표를 정하고 → 그에 맞는 교재와 과 순서를 정하고 → 진도를 따라가면서 빠르게/천천히 조정하거나 교재를 바꾼다.**
- 지금은 학생마다 `goals`(자유 문장), `target_level`, `persona`(→ 중심 교재를 코드가 정함), `next_unit`(숫자 하나)만 있다. 계획이 없어서 "계획보다 빠르다/느리다"를 판단할 기준이 없고, 선생님이 과를 건너뛰거나 교재를 바꿀 곳도 없다. PRD F2-3(로드맵 초안)은 P2였다.
- [ADR-0029](0029-understanding-from-transcript-drives-review.md)로 수업마다 항목별 이해도가 쌓이기 시작했다. 조정 제안의 근거가 생겼다.
- [ADR-0030](0030-unit-sheets-from-materials.md)로 「한국어 1·2」 40과의 단원 시트가 생기고, 진도를 표준 ID로 센다. 다음 단계에서 `next_unit`이 "책 + 과"가 된다. 학습 계획의 경로도 "책 + 과" 목록이라 같은 곳을 바꾼다.

## 결정 (Decision)
1. **학생마다 학습 계획 하나**를 둔다. 선생님이 만들고 승인한다.
   | 칸 | 내용 |
   |---|---|
   | 목표 | 문장 + 목표 등급(기존 `target_level`) + **기한(선택)** |
   | 경로 | `[{책, 과, 회차 수}]` 순서 목록. 기본값은 중심 교재의 과 순서를 지금 위치부터 목표 등급까지 |
   | 속도 | 주 몇 회, 한 과에 기본 몇 회 |
   | 위치 | 경로에서 지금 어디인지. `next_unit`을 대신한다 |
   | 변경 기록 | 언제, 무엇을, 왜 바꿨는지 |
2. 경로는 **AI가 짜지 않는다** ([ADR-0016](0016-persona-anchor-textbook-standard-levels.md)). 중심 교재 순서가 기본이고, 선생님이 과 빼기 / 회차 더하기 / 남은 경로를 다른 교재로 바꾸기를 한다.
3. **계획 대비 진도는 코드가 계산한다.** 기한이 있으면 "오늘 있어야 할 위치"와 실제 위치를 비교해 계획대로 / 앞섬 / 뒤처짐과 "이 속도면 기한 안에 끝나는지"를 보여 준다. 기한이 없으면 진도 비교는 하지 않고 아래 제안만 한다.
4. **수업 기록을 승인할 때 코드가 다음 수업을 제안한다** (근거는 승인된 이해도·표준 ID 진도, LLM 없음):
   - **천천히**: 이번 과 문법이 "헷갈림"이면 → 이 과를 1회 더
   - **빨리**: 다음 과의 표준 항목을 이미 대부분 배웠으면(다른 교재·레벨테스트) → 그 과를 건너뛰거나 합치기
   - **계획 다시 보기**: 같은 항목이 3회 연속 "헷갈림"이거나, 기한이 있고 지금 속도로 크게 넘길 때 → 목표·경로를 다시 보자고 띄운다
   - 제안마다 근거(어느 항목이 몇 번 헷갈렸나)를 같이 보여 준다. 선생님이 승인해야 계획이 바뀐다 ([ADR-0009](0009-hitl-on-all-writes.md)). 승인 화면의 "다음에 배울 과" 숫자 칸은 이 제안 카드로 바뀐다.
5. **화면**: 학생 상세에 "학습 계획" 카드, [수업 준비] 탭 카드에 상태 배지(계획대로 / 천천히 권장 / 계획 다시 보기). 학생이 여러 명이어도 오늘 누구에게 신경을 더 써야 하는지 한눈에 보이게 한다.
6. 구현 순서: 단원 시트의 "책 + 과" 전환(수업 준비가 시트를 읽고, 화면에서 과를 고르는 일)이 끝난 뒤에 그 위에 얹는다. 같은 `Student`·`Lesson`·수업 준비 그래프를 동시에 바꾸지 않기 위해서다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 지금처럼 `next_unit`만 | 선생님이 매번 과 번호를 고친다 | 할 일 없음 | 계획이 없어 속도를 판단할 기준이 없다. 학생이 여럿이면 누가 뒤처졌는지 안 보인다 |
| B. AI가 로드맵을 짠다 (기존 F2-3) | LLM이 N회 수업 계획 초안 | 선생님 손이 덜 간다 | ADR-0016(커리큘럼은 교재 순서)과 어긋난다. 순서는 교재가 이미 정했고, 필요한 건 "어디서 속도를 바꿀까"다 |
| C. 숫자 규칙만 (예: 한 과에 예정보다 2회 넘게 쓰면 천천히) | 이해도 없이 회차로만 판단 | 단순하다 | 왜 느린지 모른다. 녹취록에서 얻은 이해도가 더 직접적인 근거다 |
| D. 지금 바로 구현 | 단원 시트 작업과 동시에 | 빨리 볼 수 있다 | 두 작업이 `next_unit` → "책 + 과" 전환을 따로 정하게 되어 부딪친다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: "목표 → 경로 → 수업 → 이해도 → 조정"의 고리가 닫힌다. 맞춤 수업의 근거가 수업 하나가 아니라 학생의 전체 계획이 된다.
- 좋은 점: 표준 ID로 세기 때문에 교재를 바꿔도 이미 배운 것을 건너뛸 수 있다.
- 대가: 학생 등록 뒤에 계획을 세우는 단계가 하나 는다. 기본 경로를 자동으로 채워서 줄인다.
- 대가: 구현이 단원 시트 작업 뒤로 밀린다.
- PRD F2-3은 "AI 로드맵 초안(P2)"에서 이 결정으로 바뀐다.

## 재검토 조건
- 제안을 선생님이 자주 무시하면 → 제안 기준(헷갈림 횟수, "대부분 배움"의 비율)을 조정한다
- 기한을 거의 쓰지 않으면 → 진도 비교 화면을 빼고 제안만 남긴다
