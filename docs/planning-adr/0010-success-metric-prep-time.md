# ADR-0010: 성공 지표는 수업 준비 시간, 서비스가 직접 측정한다
- 상태: Superseded by ADR-0020 (2026-10-20)
- 관련 모듈: `TimeLog`, `Baseline`, `/metrics/time`, 대시보드

## 배경 (Context)
서비스가 실제로 도움이 되는지 판단할 지표가 필요하다. 후보는 수업 준비 시간, 수업 후 정리 시간, 리포트 발송률, 학생 재예약률이었다. 수익 지표는 ADR-0002에서 뺐다.

## 결정 (Decision)
- **주 지표: 수업 준비 시간.** [준비 시작] 시점부터 모든 범주 승인 + PPT 생성 완료까지를 서비스가 자동으로 기록한다.
- 보조 지표: 수업 후 정리 시간 (메모 입력 시작 ~ 기록 승인 완료), 수정 없이 승인된 비율, 기록 추출 정확도
- AI 없이 했을 때의 기준 시간(baseline)은 선생님이 직접 입력해서 대시보드에서 비교한다.
- 목표 가설: 준비 시간 50% 이상 감소, 수업 후 정리 5분 이내

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 준비 시간 자동 측정 | 서비스 이벤트로 기록 | 내 pain point와 바로 연결, 혼자서도 측정 가능 | (채택) |
| B. 설문·체감 평가 | 써 본 뒤 만족도 | 쉬움 | 숫자로 비교하기 어려움 |
| C. 학생 재예약률 | 학생 유지 | 비즈니스 성과 | 데이터가 플랫폼에 있고, 기간이 짧아 측정 불가 |

## 결과 / 트레이드오프 (Consequences)
- 시간 측정용 엔티티(`TimeLog`, `Baseline`)를 추가한다.
- 기준 시간은 제출 전에 AI 없이 수업 1회를 직접 준비해서 잰다. 못 하면 과거 경험의 추정치를 쓰되 "추정"이라고 표시한다.

## 재검토 조건
- 수업 준비보다 수업 후 정리가 더 큰 문제로 드러날 때
- 학생이 늘어서 재예약률 같은 지표를 볼 수 있게 될 때
