# ADR-0003: 수업 기록은 선생님 메모로 받는다 (녹음 분석은 나중에)
- 상태: Accepted, P2(녹음 파일 업로드) 항목만 Superseded by [ADR-0026](0026-transcript-text-upload.md) (2026-10-21)
- 관련 모듈: `agent/post_lesson/`, `/lessons/{id}/record`

## 배경 (Context)
Preply와 AmazingTalker는 공개 API가 사실상 없어서 수업 내용을 자동으로 가져올 수 없다. 수업 후 기록을 서비스에 넣는 방법을 정해야 한다.
후보는 (a) 선생님의 짧은 메모·음성 메모, (b) 수업 녹화·녹음 파일 업로드 → STT, (c) 수업 채팅 로그 붙여넣기였다. 나는 (a)나 (b)를 원했다.

## 결정 (Decision)
- **MVP(P0)**: 수업 후 자유 형식 **텍스트 메모**를 받는다. AI가 다룬 교재 항목, 잘한 점, 틀린 점, 약점 변경, 숙제, 피드백 메시지로 구조화한다.
- **P1**: 브라우저에서 음성 메모 녹음 → STT
- **P2**: 수업 녹화·녹음 파일 업로드 → STT → 분석

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 텍스트 메모 | 수업 직후 몇 줄 입력 | 바로 구현 가능, 선생님 판단이 들어간 정보 | (채택, P0) |
| A'. 음성 메모 | 말로 남기고 STT | 입력이 가장 편함 | 반나절이 더 들어서 P1로 미룸 |
| B. 녹음 파일 분석 | 50분 녹음 전체를 STT로 분석 | 선생님이 할 일이 거의 없음 | 긴 오디오 처리, 화자 구분, 비용, 학생 동의 문제. 마감 안에 어려움 → P2 |
| C. 채팅 로그 붙여넣기 | 플랫폼 수업 채팅 복사 | 구현이 쉬움 | 채팅에는 수업 내용 일부만 남음 |

## 결과 / 트레이드오프 (Consequences)
- 메모가 짧거나 모호하면 추출이 부정확할 수 있다. 수업 준비 때 만든 구성안을 기본값으로 쓰고(F4-5), 모르는 부분은 비워 두게 해서 보완한다.
- 녹음을 안 쓰니 MVP에서는 실제 개인정보(음성) 문제가 생기지 않는다 (ADR-0011).

## 재검토 조건
- 직접 써 보니 메모 쓰는 시간이 수업 후 정리 목표(5분)를 넘을 때 → 음성 메모를 P0로 올린다
- 메모만으로 추출 정확도가 80%를 넘지 못할 때
