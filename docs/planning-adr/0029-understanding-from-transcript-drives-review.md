# ADR-0029: 녹취록에서 항목별로 "헷갈려 보인 것"을 찾아 다음 수업 복습에 반영한다
- 상태: Accepted (2026-10-21)
- 관련 모듈: `ai-server/app/agent/post_lesson/`, `ai-server/app/agent/lesson_prep/nodes.py`, `frontend/src/pages/LessonRecordPage.vue`
- 기술 설계: [기술 ADR-0033](../adr/0033-observe-judge-understanding.md)
- 관련 ADR: [ADR-0026](0026-transcript-text-upload.md) (녹취록 올리기, 4번 글자 수 상한만 이 ADR이 대체), [ADR-0009](0009-hitl-on-all-writes.md), [ADR-0015](0015-no-ppt-fixed-lesson-frame.md) (7단계 틀의 복습 단계)

## 배경 (Context)
- 실제로 가르칠 때는 "목표 → 교재 → 진도를 따라가며 빠르게/천천히 조정"을 한다. 지금 기획에는 수업 하나를 준비하는 기능만 있고, 수업에서 본 학생 반응이 다음 수업에 반영되는 고리가 약하다.
- 지난 수업 복습은 7단계 틀에 이미 필수로 들어가 있다 (2단계, 50분 기준 5분). 하지만 복습 항목은 "약점 → 직전 수업 문법 → 직전 수업 어휘" 순서로 늘 같은 규칙으로 고른다. 수업 중 무엇이 헷갈렸는지는 모른다.
- 선생님은 수업 뒤에 **메모를 따로 쓰지 않고 녹취록만 올리려 한다.** 헷갈려 보인 부분은 AI가 찾아 주기를 바란다.
- 50분 수업 녹취록은 8,000자(ADR-0026 상한)를 넘기 쉽다. ADR-0026의 재검토 조건("녹취록을 자주 올리고 8,000자 제한이 불편하면")에 해당한다.

## 결정 (Decision)
1. **지난 시간 복습은 매 수업 필수로 둔다** (지금과 같음, 배운 것이 없는 첫 수업만 뺀다).
2. 수업 후 기록에서 **이번 수업에 다룬 항목마다 이해도(헷갈림 / 조금 헷갈림 / 괜찮음)** 를 정한다.
   - AI는 녹취록에서 학생의 반응 장면(틀림, 다시 물어봄, 망설임, 선생님이 다시 설명함, 스스로 고침, 바로 맞힘)을 **원문 인용과 함께** 찾는다.
   - 이해도 판정은 장면을 세어 **코드 규칙**으로 한다. LLM에게 "복습이 필요한가?"를 바로 묻지 않는다.
   - 인용이 녹취록에 없으면 버린다. 장면이 없는 항목은 이해도를 붙이지 않는다 ("모름").
3. 선생님은 기록 승인 화면에서 이해도를 확인하고 바꿀 수 있다. 승인한 이해도만 남는다 (ADR-0009).
4. 다음 수업 준비의 복습 항목은 **지난 수업에서 헷갈림 → 조금 헷갈림 → 약점 → 나머지 직전 수업 항목** 순서로 고른다.
   헷갈림 항목이 복습에 들어가면 복습 시간을 두 배로 늘린다 (늘린 만큼 활용 활동에서 뺀다).
5. 녹취록·메모 글자 수 상한을 **30,000자**로 올린다 (ADR-0026 4번 대체). 50분 녹취 전체가 들어간다.
6. **판정 정확도는 이번 목표가 아니다** (ADR-0026 5번과 같은 입장). 녹취록 → 이해도 → 복습으로 이어지는 흐름이 돌아가면 되고, 틀린 판정은 선생님이 승인 화면에서 고친다. 정확도 평가 데이터셋이나 프롬프트 튜닝은 하지 않는다.
7. 이번에는 "이해도 → 복습"까지만 한다. 학습 계획(목표·기한, 교재와 과 순서, 진도 속도)과 "천천히/빨리/교재 다시 보기" 제안은 다음 단계에서 이 이해도 기록을 근거로 만든다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 지금 규칙 유지 | 약점 → 직전 수업 순서 | 할 일 없음 | 수업에서 본 반응이 다음 수업에 들어가지 않는다 |
| B. LLM에게 복습 필요 여부를 바로 묻기 | "이 항목 복습 필요?" → 예/아니오 | 프롬프트 하나 | 같은 녹취록에도 답이 흔들리고, 근거를 확인할 수 없고, 기준을 조절하려면 프롬프트를 고쳐야 한다 |
| C. 선생님이 메모에 직접 쓰게 하기 | "을/를 복습" 같은 메모를 기대 | 정확 | 선생님은 녹취록만 올리려 한다 |
| D. 진도 속도·학습 계획까지 한 번에 | 계획 엔티티 + 조정 제안 | 전체 고리 완성 | 범위가 크다. 이해도 기록이 먼저 쌓여야 조정 근거가 생긴다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 녹취록만 올려도 다음 수업 복습이 "이 학생이 실제로 헷갈린 것" 중심이 된다. 근거 인용이 같이 보여서 선생님이 판정을 바로 확인할 수 있다.
- 좋은 점: 항목별 이해도가 수업마다 쌓여서, 다음 단계의 진도 조정과 진도 리포트의 근거가 된다.
- 대가: LLM 호출이 하나 늘어난다 (장면 찾기). 긴 녹취록은 토큰이 많이 든다.
- 대가: 녹취록 품질(받아쓰기 오류, 화자 구분 없음)에 따라 장면을 놓칠 수 있다. 선생님 확인으로 거른다.
- 대가: 3만 자는 로컬 모델 기본 컨텍스트(16k 토큰)를 넘을 수 있다. 로컬 모델을 쓸 때는 `OLLAMA_NUM_CTX`를 늘려야 한다.

## 재검토 조건
- 이해도 판정이 선생님 판단과 자주 다르면 → 점수 기준(코드 숫자)을 먼저 조정하고, 그래도 안 맞으면 장면 종류를 다시 본다
- 같은 항목이 여러 수업 연속 "헷갈림"이면 → 약점 자동 제안, 진도 조정(학습 계획)으로 넘어간다
