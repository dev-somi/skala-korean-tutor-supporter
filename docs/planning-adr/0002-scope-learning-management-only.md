# ADR-0002: 범위를 학습 관리로 한정한다 (예약·결제·수익 모델 제외)
- 상태: Accepted
- 관련 모듈: 전체

## 배경 (Context)
"학생 관리"라고 하면 예약, 일정, 결제, 학습 관리가 모두 들어갈 수 있다.
내가 겪은 문제는 두 가지다.
1. 수업 준비(자료 만들기, 수업 내용 공부)에 시간이 많이 든다.
2. 수업 후 노트, 피드백, 숙제를 정리하는 게 귀찮다.

예약·일정·결제는 Preply와 AmazingTalker가 이미 제공한다.

## 결정 (Decision)
- **학습 관리에만 집중한다.** "이 학생의 목표가 무엇이고, 그 목표를 위해 어떻게 가르쳐야 하는가"를 전반적으로 돕는다. 한국어 교육 경험이 많지 않은 선생님도 쓸 수 있어야 한다.
- 위 두 문제를 하나의 고리(수업 후 기록 → 프로필 갱신 → 다음 수업 준비)로 묶어서 푼다.
- 예약·일정·결제는 만들지 않는다.
- 수익 모델과 가격은 PRD에서 뺀다. 수익은 플랫폼에서 이미 나기 때문이다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 학습 관리만 | 진도, 약점, 수업 준비, 수업 후 기록 | 내 pain point에 정확히 맞음, 범위가 작음 | (채택) |
| B. 학습 관리 + 일정·예약 | 플랫폼 밖에서 일정까지 관리 | 한 곳에서 다 볼 수 있음 | 플랫폼 기능과 겹치고, 플랫폼 공개 API가 없어 동기화가 어려움 |
| C. 체험수업 전환·이탈 예측까지 | 비즈니스 지표 관리 | 수익에 직접 도움 | 지금 내 문제가 아님, 데이터도 없음 |

## 결과 / 트레이드오프 (Consequences)
- 다음 수업 날짜 같은 정보는 선생님이 직접 입력한다.
- 성공 지표가 수익이 아니라 시간 절약(ADR-0010)이 된다.

## 재검토 조건
- 학생이 많아져서 일정 관리가 실제로 문제가 될 때
- 다른 선생님에게 서비스를 팔 생각이 생길 때 (수익 모델 검토)
