# ADR-0032: 수업 준비 결과를 15장 슬라이드 구성안(학생 화면 문구 + 교사 노트)으로 낸다
- 상태: Accepted (2026-10-21)
- 관련 모듈: `ai-server/app/agent/lesson_prep/` (lesson_frame, write_slides), `frontend` (수업안 검토 화면)
- 기술 설계: [docs/adr/0034](../adr/0034-slide-plan-node.md)
- 관련 ADR: [ADR-0015](0015-no-ppt-fixed-lesson-frame.md) (7단계 틀, 이 ADR이 대체), [ADR-0017](0017-examples-from-materials-not-generated.md), [ADR-0023](0023-culture-point-from-sejong-materials.md)
- 출처: [docs/reference/온라인_한국어_1대1_수업_PPT_제작_기준.md](../reference/온라인_한국어_1대1_수업_PPT_제작_기준.md)

## 배경 (Context)
- 사용자가 평소 쓰는 수업 PPT 제작 기준 문서를 `docs/reference/`에 넣었다. 수업 준비 버튼의 결과가 그 문서가 정한 산출물과 같은 모양이길 원한다.
- 기존 결과는 7단계 진행표였다 (ADR-0015). 단계마다 "할 일" 한 줄과 범주 내용(설명·예문)을 이어 붙인 것이라, 선생님이 슬라이드를 만들려면 학생 화면에 무엇을 보일지, 질문을 어떻게 던지고 어려워하면 어떻게 도울지를 다시 짜야 했다.
- 기준 문서의 산출물: ① 수업 목표와 범위 ② 슬라이드별 구성(번호·시간·학생 화면 문구·활동) ③ 슬라이드별 교사 노트(소요 시간·목표·진행·기본 질문/예상 답변·어려워하면·잘하면·출처) ④ 숙제와 보충 자료.

## 결정 (Decision)
1. **결과를 15장 슬라이드 구성안으로 낸다.** 기준 문서 §3의 기본형을 그대로 쓴다: 안부 4분 · 복습 3분 · 목표와 짧은 대화 3분 · 어휘 6분(2장) · 표현 6분(2장) · 도움 받는 연습 10분(3장) · 자기 이야기와 역할극 12분(3장) · 문장 고치기 3분 · 마무리와 숙제 3분 = 50분. 수업 길이에 비례해 조정한다.
2. 장마다 **학생 화면에 보일 실제 문구**와 **교사 노트 7칸**을 낸다. 맨 위에 수업 목표(학생이 할 수 있어야 하는 행동 한 문장)와 최종 미션, 맨 아래에 숙제(쪽수·문항·방법·완료 예시)를 둔다.
3. **PPT 파일은 여전히 만들지 않는다** (ADR-0015 유지). 화면에서 보고 글로 복사한다.
4. **교재에 없는 정보는 만들지 않고 "확인 필요"로 표시한다**: 숙제 쪽수·문항, 음원 번호, 이전 학습 이력(기준 §4, §7, §11). 복습할 이전 수업이 없으면 2번 장은 같은 시간에 수준 확인 질문을 쓴다.
5. 14번 장(문장 고치기)은 **수업 중에 나온 실제 오류를 적는 빈 칸**이다. 예상 오류를 학생이 한 말처럼 미리 쓰지 않는다.
6. 4범주(복습·새 어휘·새 문법·숙제) 검토와 승인·수정·피드백 흐름은 그대로 둔다. 구성안은 그 승인된 내용을 재료로 쓴다.
7. 문화 포인트(ADR-0023)는 구성안 아래에 그대로 보인다. "도입 단계에 붙인다"는 결정은 15장에서는 "구성안 옆에 같이 보인다"로 바뀐다 (시간은 그대로 어휘·표현 단계 안에서 쓴다).

## 검토한 대안 (Alternatives)
| 대안 | 장점 | 기각 이유 |
|---|---|---|
| 7단계 틀 유지 + 단계 안에 슬라이드 목록 | 바꿀 곳이 적다 | 화면이 길어지고, 단계와 슬라이드 두 단위가 섞인다. 사용자가 원하는 모양은 15장 표다 |
| PPT 파일 생성 | 바로 수업에 쓴다 | ADR-0015에서 뺀 이유(내용이 아닌 모양에 드는 노력)가 그대로다. 요구도 "구성안"이다 |
| 슬라이드 내용을 코드로만 조립 | 빠르고 안전하다 | 학생 화면 문구, 확인 질문, 어려워하면/잘하면은 기존 초안·브리핑을 배치만 해서는 비거나 빈약하다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 선생님이 구성안을 보고 바로 자기 PPT에 옮길 수 있다. 목표·최종 미션이 맨 위에 나와 수업 설계가 거꾸로(미션 먼저) 읽힌다.
- 대가: 수업 준비에 LLM 호출이 한 번 늘어난다. 선생님이 범주를 고치면 확정할 때 한 번 더 든다.
- 대가: 검토 중에 보이는 구성안은 선생님이 고치기 전 초안 기준이다 (확정할 때 맞춘다).
- 대가: 구성안 문구는 LLM이 쓰므로 기준 문서 규칙을 어길 수 있다. 코드 점검(장 수·시간·어휘 분량·숙제 표시)만 자동이고 나머지는 선생님이 읽고 판단한다.

## 재검토 조건
- 15장이 길어서 부담스럽다는 선생님이 많으면 → 15장을 접어서 보는 요약(단계별 한 줄) 기본 화면
- 슬라이드 파일(PPTX)이 필요해지면 → 이 구성안을 그대로 내보내는 기능
