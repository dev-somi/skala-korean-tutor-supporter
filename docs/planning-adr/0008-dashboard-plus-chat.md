# ADR-0008: UI는 대시보드 GUI + 채팅
- 상태: Accepted
- 관련 모듈: 프론트엔드, `/chat/stream`, `agent/router/`

## 배경 (Context)
후보는 (a) 학생 목록 대시보드 + 학생별 상세 + 기능 버튼, (b) 채팅형 에이전트만, (c) 대시보드 + 채팅 보조였다.

## 결정 (Decision)
**(c) 대시보드 GUI와 채팅을 둘 다 제공한다.**
- 대시보드: 학생 목록, 학생 상세, 할 일(미처리 기록, 승인 대기), 검토 화면, 시간 통계
- 채팅: 조회 질문("유이 요즘 약한 거 뭐야?")과 작업 요청("Emma 다음 수업 준비해줘")
- 채팅 앞단에 **라우팅 게이트(저가 모델)** 를 두어 단순 조회에는 무거운 그래프를 돌리지 않는다 (참고노트 설계 결정 7).

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 대시보드만 | 버튼과 폼 | 검토·승인 화면 만들기 쉬움 | 간단한 조회도 화면을 찾아 들어가야 함 |
| B. 채팅만 | 모든 작업을 대화로 | 구현할 화면이 적음 | 범주별 검토, 학생 목록 보기 같은 작업은 대화로 불편함 |
| C. 대시보드 + 채팅 | 둘 다 | 각자 잘하는 일을 맡김 | (채택) |

## 결과 / 트레이드오프 (Consequences)
- 만들 화면이 늘어난다. 시간이 모자라면 채팅은 조회만 남긴다 (PRD 11장 빼는 순서).
- HITL 검토는 대시보드 검토 화면에서 하고, 채팅은 그 화면으로 연결한다.

## 재검토 조건
- 직접 써 보니 채팅을 거의 안 쓰거나, 반대로 대시보드를 거의 안 쓸 때
