# ADR-0009: AI는 DB에 직접 쓰지 않는다 (모든 쓰기에 HITL)
- 상태: Accepted
- 관련 모듈: `agent/*`, `persistence/`

## 배경 (Context)
AI가 만든 결과(학생 정보, 약점 변경, 수업 기록, 수업안)를 바로 반영할지, 선생님 확인을 거칠지 정해야 한다. 잘못된 약점이나 수업 이력이 쌓이면 다음 수업 준비가 계속 틀어진다. 나는 HITL이 필요한 곳에 많이 들어가야 한다고 판단했다.

## 결정 (Decision)
**AI는 DB에 직접 쓰지 않는다. 모든 쓰기는 "초안 → 선생님 확인(승인/수정/피드백) → 반영" 순서로 한다.**

| 지점 | 선생님이 하는 일 |
|---|---|
| 학생 등록·수정 (자연어 → AI 채움) | 초안 확인 후 저장 |
| 수업안 | 범주별 승인 / 직접 수정 / 피드백 (기존 방식) |
| 선생님 브리핑 | 확인 |
| 수업 후 기록 | 항목별 승인 후 프로필·이력에 반영. 승인 전에는 "미처리 기록" |
| 약점 추가·해제 | 항목별 승인 |
| 학생 피드백 메시지 | 확인 후 선생님이 직접 보냄 |

조회와 자료 미리보기만 승인 없이 한다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 모든 쓰기에 HITL | 위 표 | 데이터 품질 보장, AI 실수가 쌓이지 않음 | (채택) |
| B. 자동 반영 + 나중에 수정 | AI가 바로 쓰고 선생님이 고침 | 클릭 수가 적음 | 틀린 내용을 놓치기 쉽고, 다음 수업 준비에 그대로 들어감 |
| C. 신뢰도 높은 것만 자동 반영 | 신뢰도 기준으로 나눔 | 균형 | 신뢰도 기준을 정할 데이터가 아직 없음 |

## 결과 / 트레이드오프 (Consequences)
- 검토 화면이 많아져서 프론트 작업이 늘어난다.
- 승인 단계 때문에 시간이 더 들 수 있다. 그래서 시간 측정(ADR-0010)에서 AI 대기 시간과 선생님 검토 시간을 나눠 본다.
- 선생님 확인과 별개로, LLM이 만든 교재 ID·약점 변경은 코드가 먼저 검사한다 (권위 게이트).

## 재검토 조건
- "수정 없이 승인" 비율이 계속 높은 항목이 있으면, 그 항목은 자동 반영(대안 C)으로 바꾸는 것을 검토한다.
