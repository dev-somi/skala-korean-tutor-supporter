# ADR-0016: 표준 등급 목록은 ai-server 파일 데이터로 두고, 교재 항목과는 대응표로 잇고, 예문 등급은 Kiwi 형태소 분석으로 판정한다
- 상태: Accepted (2026-10-20), 결정 4(약점 ID는 교재 ID 유지)만 Superseded by [ADR-0032](0032-unit-sheets-and-standard-ids.md) (2026-10-21)
- 관련 모듈: `ai-server/app/standard/` (`importer.py`, `levels.py`), `ai-server/data/standard/`, `ai-server/tests/test_standard_levels.py`
- 관련 ADR: [기획 ADR-0016](../planning-adr/0016-persona-anchor-textbook-standard-levels.md), [기획 ADR-0017](../planning-adr/0017-examples-from-materials-not-generated.md), [ADR-0005](0005-data-access-ownership.md), [ADR-0013](0013-process-over-model.md), [ADR-0014](0014-teaching-material-rag.md)

## 배경 (Context)
국립국어원 등급 목록(1~6급, 문법 336개, 어휘 10,635개)을 공통 기준으로 쓰기로 했다. 정할 것:
- 데이터를 어디에, 어떤 형식으로 둘지
- 표준 항목 ID와, 교재 항목 ID(`u03-g02`)와의 관계
- 예문의 어휘 등급을 어떻게 판정할지

원본 엑셀을 열어 보고 확인한 사실:
- 어휘 표제어에 동음이의 번호가 붙어 있다 (`가격02`). 품사가 여럿인 206개는 한 칸에 묶여 있다 (`그02/그01`, `첫째02‧첫째01/첫째03`). 구분자가 `/ ‧ ∙ ·`로 섞여 있다.
- 같은 글자가 품사마다 등급이 다르다 (`가`: 명사 5급만 있음).
- 품사 칸도 `관형사∙명사`, `부사/명사`처럼 겹쳐 있다.
- 교재 문법 하나가 표준 항목 여러 개에 걸친다 (`-습니다, -습니까` → 2개). 표준 목록에 문법으로 없는 것도 있다 (`이/가 아니다`의 `아니다`는 어휘 1급).

## 결정 (Decision)
1. **데이터**: 엑셀을 `app/standard/importer.py`로 `data/standard/grammar.json`, `vocab.json`으로 바꿔 저장소에 넣는다 (공공누리 제1유형, 파일 안에 출처를 적는다). 원본 엑셀도 `data/standard/source/`에 둔다. openpyxl은 가져오기에서만 쓰므로 dev 의존성이다.
2. **ID**: 엑셀의 "전체 번호"로 만든다. 문법 `std-g-007`, 어휘 `std-v-00001`. 원본을 다시 받아도 번호가 같으면 ID가 같다. 묶인 표제어는 글자 하나로 합치고 번호는 `homonym`에 `02/01`로 남긴다.
3. **교재 → 표준 대응표**: `data/standard/textbook_map.json`에 `{교재: {교재 항목 ID: [표준 ID, ...]}}`로 둔다. 1:N이고, 문법이 없으면 어휘 ID로 잇는다. 교재 JSON에 칸을 더하지 않는다. 교재 데이터는 저작권 때문에 git에 넣지 않지만, 대응표에는 교재 원문이 없어서 저장소에 남길 수 있다. 교재 항목의 등급 = 대응 표준 항목 중 가장 높은 등급.
4. **약점 ID는 지금은 교재 ID를 유지한다.** 등급·진척도는 대응표로 계산한다. 약점을 표준 ID로 옮기는 일(Spring Flyway 마이그레이션, intake·post_lesson 권위 게이트 수정)은 두 번째 교재 데이터가 들어올 때 한다. 교재가 하나인 동안에는 교재 ID만으로 끊기는 기록이 없다.
5. **예문 어휘 등급**: Kiwi(`kiwipiepy`)로 형태소를 나누고, 내용어(일반명사·의존명사·수사·대명사·동사·형용사·부사·관형사·감탄사)를 사전형으로 바꿔(어간 + 다, 어근 + 하다, 선생 + 님) 품사가 맞는 표제어의 가장 낮은 등급을 찾는다. 문장 등급 = 가장 높은 단어 등급.
   - 보조용언(`-고 싶다`, `-지 않다`)은 문법 표현이라 세지 않는다. 안 빼면 `않다`(3급 동사) 때문에 `먹지 않아요`가 3급이 된다.
   - 품사가 맞는 표제어가 없으면 다른 품사의 등급을 빌려 오지 않고 `unknown`으로 돌려준다. 고유명사도 세지 않는다. 틀린 등급보다 모름이 낫다.
   - 대화 예문의 화자 표시(`가:`, `나:`)는 지운다. 안 지우면 `가`가 명사 5급으로 잡힌다.
   - (2026-10-20 보완) 원본 품사 칸은 `부사/명사`, `수사.관형사/명사`처럼 묶여 있어 구분자로 쪼개 **정확히** 맞춘다. 처음에는 "포함"으로 맞춰서 `명사`가 `의존명사`·`대명사`에도 걸렸다. 다만 명사·의존명사는 한쪽으로만 넓힌다: Kiwi의 명사는 목록의 의존명사와도 맞추고(`받을 때`의 때 = 의존명사 1급, 명사 `때가 타다` 4급이 아님), Kiwi의 의존명사는 의존명사만 본다(`본 적이 있다`의 적이 명사 `적(敵)` 4급이 되지 않게). 둘을 가르는 기준이 Kiwi와 목록이 달라서다.
6. **소유**: Spring이 아니라 ai-server가 가진다. 정적 참고 자료라 앱 데이터가 아니고, 교재 JSON·RAG 색인과 같은 이유다 ([ADR-0005](0005-data-access-ownership.md), [ADR-0014](0014-teaching-material-rag.md)).

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| Postgres 테이블 | Flyway로 등급 목록 적재 | 진척도를 SQL로 계산 | ai-server가 읽어야 하는데 DB 접근은 Spring만 한다 (ADR-0005). 바뀌지 않는 참고 자료다 |
| 교재 JSON에 `standard_id` 칸 | 항목마다 표준 ID | 한 파일에서 본다 | 교재 데이터는 git에 넣지 않아서 대응 결과가 저장소에 안 남는다. 1:N을 담기 어색하다 |
| 형태소 분석 없이 글자 맞추기 | 문장을 띄어쓰기로 자르고 목록과 비교 | 의존성 없음 | `갑니다`, `좋아합니다` 같은 활용형을 못 찾는다 |
| KoNLPy (Mecab, Okt) | 널리 쓰는 분석기 | 자료가 많다 | Java나 시스템 라이브러리가 필요하다. Kiwi는 pip 하나로 설치되고 macOS에서 바로 돈다 |
| LLM에게 등급 판정 | "이 문장 몇 급이야?" | 문법까지 본다 | 결과가 매번 다르고 근거가 없다. 정답이 있는 일은 코드로 한다 (ADR-0013) |

## 결과 / 트레이드오프 (Consequences)
- 확인 결과: 「한국어 1」 2~4과 예문 53개 중 52개를 1급으로 판정했다. 나머지 1개는 `따라 하세요` → `따르다`(3급)이다. 목록 밖 단어는 `안녕`(목록에는 감탄사만 있음), `케이`·`팝`(K-pop)뿐이다. 회귀 검사로 테스트에 넣었다.
- 대가: `kiwipiepy` 모델이 약 100MB이고, 첫 호출에 분석기를 띄우는 데 1초쯤 걸린다 (한 번만 띄운다).
- 대가: 문법 표현의 등급은 보지 않는다 (기획 ADR-0017의 대가).
- 대가: 대응표는 사람이 검수해야 한다. 테스트는 대응표의 ID가 실제로 있는지와, 교재 문법이 빠짐없이 대응되는지만 본다.

## 재검토 조건
- 두 번째 교재 데이터가 들어오면 → 약점 ID를 표준 ID로 옮긴다 (결정 4)
- 예문 문법 등급이 필요해지면 → Kiwi 형태소 열을 문법 대표형·관련형 패턴과 맞추는 판정기를 더한다
- 동음이의어 때문에 등급이 틀리는 사례가 쌓이면 → 길잡이말(`학교에 가다`)과 문맥을 비교해 표제어를 고른다
