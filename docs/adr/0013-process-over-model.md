# ADR-0013: 좋은 모델보다 정형화된 절차 — LLM은 작은 칸만 채운다
- 상태: Accepted (2026-10-20) — 결정 3(auto_review LLM 검사 유지)만 Superseded by ADR-0021 (2026-10-20)
- 관련 모듈: `ai-server/app/agent/lesson_prep/` (`plan_lesson`, `briefing`), `ai-server/prompts/teacher_briefing.md`
- 관련 ADR: [ADR-0007](0007-llm-provider-tiering.md), [ADR-0012](0012-local-ollama-for-dev.md), [ADR-0014](0014-teaching-material-rag.md)

## 배경 (Context)
지금 수업 준비 그래프는 "좋은 모델이 알아서 잘 만든다"를 전제로 한다.
- `plan_lesson`: LLM이 항목 선택, 시간 배분(합계를 수업 시간에 맞추기), 이유를 한 번에 정한다. 합계가 틀리면 `auto_review`에서 실패해 최대 3번 다시 계획한다.
- `briefing`: "모국어 화자가 자주 틀리는 점", "예상 질문"을 LLM 지식에서 만든다. 근거가 없다.

로컬 `qwen3:8b`([ADR-0012](0012-local-ollama-for-dev.md))로 돌려 보면 여러 제약을 동시에 지키는 판단과 지식이 필요한 생성에서 품질이 크게 떨어진다. 그런데 이 두 일은 사실 LLM이 할 필요가 없다. 진도와 시간 배분에는 정답 규칙이 있고, 문법의 공식 설명과 수업 절차는 교원용 지침서에 있다 ([기획 ADR-0013](../planning-adr/0013-sejong-public-materials.md)).

## 결정 (Decision)
원칙: **정답이 있는 건 코드가, 지식은 자료가, LLM은 고르기·채우기·다듬기만 한다.**

1. **`plan_lesson`을 코드 규칙으로 바꾼다.**
   - 새 어휘·문법: 이번 과의 항목을 교재 순서대로
   - 복습: 해결되지 않은 약점 중 배운 항목 → 직전 수업 항목 순서로, 최대 몇 개
   - 숙제: 이번 과의 연습문제
   - 시간: 수업 길이에 대한 고정 비율 (복습 20%, 어휘 25%, 문법 45%, 숙제 10%; 복습할 게 없으면 복습 몫을 문법에 준다). 반올림 오차는 문법에 몰아서 합계가 항상 맞게 한다
   - 이유(reason)도 규칙으로 쓴다 ("약점 2개 + 직전 수업 항목")
2. **`briefing`은 근거를 먼저 모으고, LLM은 개인화 칸만 쓴다.**
   - 코드가 모음: 이번 과·문법에 해당하는 지침서 구역(학습 목표, 수업 절차, 문법 제시·연습, 지도의 유의점)과 핸드북 설명 ([ADR-0014](0014-teaching-material-rag.md)의 ID 필터 경로)
   - LLM이 씀: 근거를 바탕으로 한 문법별 설명 포인트, 이 학생의 모국어 화자가 틀리기 쉬운 점, 예상 질문, 이 학생에 맞춘 팁
   - 결과에 **출처(책·쪽)**를 붙인다. 출처는 LLM이 아니라 코드가 붙인다
3. `write_explanation`, `write_script`, `auto_review`의 LLM 검사는 이번에는 그대로 둔다. 구성안이 코드로 만들어지므로 ID·복습·시간 합계 검사는 항상 통과해 재계획 루프가 사실상 없어진다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| 지금처럼 큰 모델에 맡기기 | Sonnet으로 품질 확보 | 코드 변경 없음 | 로컬 모델에서는 쓸 수 없고, 브리핑 근거가 없어 선생님이 검증할 방법이 없다 |
| 프롬프트만 더 다듬기 | few-shot, 규칙 추가 | 구조 변경 없음 | 시간 합계·ID 같은 제약은 프롬프트로 100% 지켜지지 않는다. 지식 부족은 프롬프트로 해결되지 않는다 |
| 모든 LLM 노드를 템플릿화 | 설명·대본도 틀에 끼우기 | 로컬 모델에서 가장 안정적 | 마감 안에 다 못 한다. 효과가 큰 두 노드부터 바꾼다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 구성안이 결정적이고 즉시 나온다. LLM 호출이 줄어 수업 준비가 빨라진다. 브리핑에 근거와 출처가 생긴다.
- 대가: 구성 규칙이 단순하다. "이번 수업은 회화 위주로"처럼 특별한 요청은 선생님이 검토 화면에서 고쳐야 한다.
- 대가: 브리핑 품질이 OCR·검색 품질에 기댄다.
- 측정: 같은 평가셋을 qwen3:8b와 Sonnet으로 돌려 바꾸기 전후 격차를 비교한다 (PRD 10장).

## 재검토 조건
- 선생님이 구성안을 자주 크게 고친다면 → 규칙에 학생 목표 유형을 넣거나, LLM이 규칙 결과를 조정하는 단계를 둔다
- 설명·대본 품질이 로컬 모델에서 문제가 되면 → 지침서의 교사 발화 예시를 틀로 쓰는 템플릿화를 진행한다
