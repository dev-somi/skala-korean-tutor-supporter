# ADR-0031: 일괄 색인 — 책 목록 catalog.json + 한 권씩 이어서 도는 batch + 임베딩 캐시
- 상태: Accepted (2026-10-21)
- 관련 모듈: `ai-server/app/rag/catalog.json`, `ai-server/app/rag/batch.py`, `ai-server/app/rag/index.py` (`embed`), `ai-server/app/rag/ocr.py`, `ai-server/app/rag/chunk.py`
- 기획: [기획 ADR-0028](../planning-adr/0028-index-all-materials.md)
- 관련 ADR: [ADR-0014](0014-teaching-material-rag.md), [ADR-0025](0025-form-key-tags-and-merged-editions.md), [ADR-0030](0030-local-pdf-open-via-ai-server.md)

## 배경 (Context)
- 기획 ADR-0028로 남은 PDF 124권을 넣는다. OCR이 약 12시간 걸린다. 그동안 잠자기·종료·오류로 끊길 수 있다.
- 지금까지는 책마다 `BOOKS`(chunk.py)에 손으로 한 줄씩 적고 `ocr` 명령을 따로 돌렸다. 124권은 손으로 하기 어렵다.
- `ocr.run`은 이미 OCR한 쪽을 건너뛴다(쪽 단위 이어 하기). 하지만 쪽 JSON을 쓰는 도중에 끊기면 반쯤 쓴 파일이 "끝난 쪽"으로 남는다.
- `index.build_index`는 매번 모든 조각을 처음부터 임베딩한다. 조각이 2,700개 → 수만 개가 되면 끊겼을 때 처음부터 다시 해야 한다.

## 결정 (Decision)
1. **책 목록 `app/rag/catalog.json`**: 책마다 `{id, file(자료 폴더 기준 경로), title, pages, layout, lang, kind, tier, index, ja}`. 파일 이름과 제목만 있고 교재 내용은 없어서 저장소에 둔다. `chunk.BOOKS`가 읽어 들인다 (손으로 맞춘 기존 24권이 우선). 형식은 `ocr_page`(스캔) / `text_page`(글자 층)로 한 쪽 = parent 하나 (ADR-0025 결정 8의 기본 규칙).
2. **`python -m app.rag.batch run <자료 폴더>`**: tier 순서로 한 권씩 뽑는다. 한 권이 끝날 때마다 `data/rag/batch/state.json`(원자적 쓰기)과 `batch.log`(시각 포함)에 남긴다.
   - 다시 실행하면 `done`인 책은 건너뛰고, `running`으로 남은 책(강제 종료·전원)은 "지난번에 끊김"으로 적고 끝난 쪽 다음부터 잇는다.
   - 한 권이 실패하면 `failed`와 이유를 남기고 다음 책으로 간다. 다시 실행하면 다시 시도한다.
   - 잠금 파일(`flock`)로 두 개가 동시에 돌지 않게 한다.
   - (2026-10-21 추가) `--workers N`: 책 N권을 동시에 뽑는다. 시간은 외부 프로그램(`pdftoppm`, Vision)이 쓰므로 스레드로 충분하다. 한 권은 한 스레드가 맡고, 상태 파일·로그·PDF 등록부(`pdfs.json`)는 잠그고 쓴다. M5(10코어)에서 1권 → 4권으로 분당 60~70쪽 → 268쪽.
   - `--index`를 주면 다 뽑은 뒤 색인까지 만든다. `status`로 진행 상황을 본다.
3. **OCR 쪽 JSON은 `.part`에 쓰고 이름을 바꾼다**: 반쯤 쓴 파일이 끝난 쪽으로 남지 않는다.
4. **임베딩 캐시 `data/rag/embed_cache/<모델>/`**: 글의 SHA-1 → 벡터. 32개 묶음마다 벡터를 먼저, 키를 나중에 덧붙인다. 읽을 때는 키 개수 × 차원(`dim` 파일)만큼만 믿는다. 색인을 다시 만들면 새 조각만 임베딩한다. 검색 질문은 캐시에 넣지 않는다.
5. 원본 PDF 위치는 OCR이 끝날 때 등록부에 자동으로 적힌다 ([ADR-0030](0030-local-pdf-open-via-ai-server.md)) → 새 책도 "원문" 버튼이 바로 된다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| 셸 스크립트로 ocr 명령 나열 | 책마다 한 줄 | 단순하다 | 어디까지 했는지 기록·실패 후 계속하기를 따로 만들어야 한다. 124줄을 손으로 써야 한다 |
| `BOOKS`(파이썬)에 124줄 추가 | 기존 방식 | 한 곳에서 본다 | 목록이 코드보다 길어진다. 자동으로 만든 목록을 손으로 맞춘 규칙과 섞으면 읽기 어렵다 |
| 책마다 색인 파일 따로 | 책 단위로 이어 하기 | 책 하나만 다시 만들기 쉽다 | 검색이 여러 파일을 합쳐야 한다. 언어판 합치기(ADR-0025)가 책 경계를 넘는다. 캐시로 같은 효과를 낸다 |
| 책마다 별도 프로세스 | 한 권이 죽어도 다른 책은 산다 | 격리 | 예외 처리로 충분하다. Vision 실패는 예외로 올라온다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 명령 하나로 밤새 돌리고, 어디서 끊겨도 같은 명령으로 잇는다. 시험: 58쪽 OCR 중 중단 → 다시 실행 → 28쪽부터 이어서 끝남. 색인을 다시 만들 때 이미 임베딩한 조각은 재사용한다.
- 대가: 캐시는 지운 책의 벡터도 남긴다 (용량만 차지). 모델을 바꾸면 폴더가 따로 생긴다.
- 대가: 새 책은 쪽 단위 조각이라 과·구역 필터(브리핑 경로)는 아직 못 쓴다. 의미 검색과 `mentions` 태그로만 찾는다.

## 재검토 조건
- 조각이 수만 개를 넘어 검색이 느려지면 → ADR-0014 재검토 조건대로 벡터 DB(sqlite-vec 등)
- 책 종류(본책·익힘책)별 구역 규칙을 만들면 → 그 책의 layout을 `sections`처럼 바꾸고 catalog에 반영한다
