# ADR-0010: 채팅의 작업 요청은 화면으로 넘긴다
- 상태: Accepted (2026-10-19)
- 관련 모듈: `backend/chat/ChatService.java`, `frontend/src/components/ChatWidget.vue`

## 배경 (Context)
PRD F6-3: "작업 요청은 해당 그래프를 실행하고 SSE로 진행 단계를 보여 준다. HITL 단계에서는 대시보드의 검토 화면으로 연결."
수업 준비는 몇 분이 걸리고(자동 검토 재시도 포함), 결국 범주별 검토 화면이 필요하다. 수업 후 기록도 항목별 체크 화면이 필요하다.

## 결정 (Decision)
채팅은 **수업을 만들고(또는 고르고) 해당 화면으로 가는 버튼(action 이벤트)**만 준다. 그래프 실행과 진행 표시는 그 화면이 한다.
- "유이 다음 수업 40분으로 준비해줘" → 수업 생성 → [수업 준비 화면 열기] → 화면에 들어가면 준비가 자동으로 시작된다
- 수업 메모를 채팅에 쓰면 → 가장 최근의 기록 안 한 수업을 고르고 → [수업 후 기록 화면 열기] (메모가 미리 채워짐)
- 새 학생 설명 → 등록 초안 생성 → [학생 카드 초안 확인하기] (폼이 미리 채워짐)
- 조회·일반 질문은 채팅 안에서 바로 답한다

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| 채팅 안에서 그래프 실행 + 진행 표시 | 채팅 SSE에 lesson_prep 이벤트를 중계 | PRD 문구와 가장 가깝다 | 같은 진행 표시를 두 곳(채팅·검토 화면)에 만들어야 하고, 어차피 검토는 화면에서 해야 한다. 채팅 창을 닫으면 실행이 끊긴다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 그래프 실행 경로가 하나라 버그가 한 곳에만 생긴다. 채팅 SSE가 짧게 끝난다.
- 대가: 채팅만 보고 있으면 진행 단계가 안 보인다 (버튼을 눌러야 함). PRD "빼는 순서" 1번(F6-3 SSE 진행 표시)과 같은 방향이다.

## 재검토 조건
- 채팅에서 바로 끝낼 수 있는 작은 작업(예: "숙제만 바꿔 줘")이 늘어나면 → 그런 작업만 채팅 안에서 실행
