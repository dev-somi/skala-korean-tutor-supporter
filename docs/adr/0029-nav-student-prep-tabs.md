# ADR-0029: 주 메뉴를 "학생 / 수업 준비"로 나누고, 수업 준비 결과는 브리핑부터 보여 준다
- 상태: Accepted (2026-10-21)
- 관련 모듈: `frontend/src/App.vue`, `frontend/src/router.ts`, `frontend/src/pages/PrepPage.vue`, `frontend/src/components/PrepDialog.vue`, `frontend/src/pages/LessonReviewPage.vue`, `frontend/src/pages/StudentDetailPage.vue`, `frontend/src/pages/LessonRecordPage.vue`
- 관련 ADR: [기획 ADR-0008](../planning-adr/0008-dashboard-plus-chat.md) (대시보드 + 채팅), [기획 ADR-0026](../planning-adr/0026-transcript-text-upload.md) (녹취록 텍스트 올리기)

## 배경 (Context)
- 상단 메뉴가 7개(대시보드·학생·레벨테스트·커리큘럼·어휘문법·지표·AI 추적)였다. 선생님이 매일 쓰는 건 학생과 수업 준비뿐이다.
- 수업 준비는 메뉴에 없었다. 학생 상세의 "다음 수업 준비" 다이얼로그로만 들어갈 수 있었다.
- 수업 준비 결과 화면은 7단계 틀 → 브리핑 → 범주 검토 순서였다. 수업 직전에 먼저 볼 "오늘 문법을 어떻게 설명하나"가 아래로 밀렸고, 누구를 위한 준비인지도 제목의 이름 하나로만 보였다.

## 결정 (Decision)
1. **주 메뉴는 대시보드 · 학생 · 수업 준비 세 개다.** 레벨테스트, 커리큘럼·페르소나, 어휘·문법, 지표, AI 추적은 "더보기"(PrimeVue `Menu` popup)로 묶는다.
2. **학생 탭은 학생 기준이다.** 프로필·목표·약점·진도 리포트·수업 이력을 보고, 수업 후 기록(메모 또는 녹취록)을 남긴다. `/lessons/:id/record`도 학생 탭으로 표시한다.
3. **수업 준비 탭(`/prep`)은 학생 프로필 카드를 다음 수업 일정 순으로 보여 준다.** 카드에는 다음 수업(날짜·오늘/내일/n일 뒤, 회차·과), 모국어·등급·학습 목적·약점, 그리고 상태에 맞는 버튼 하나(준비 중 → [이어서 준비], 확정 → [수업안 보기], 다음 수업 없음 → [수업 준비])가 있다. 순서는 날짜 있는 수업 → 날짜 미정 → 다음 수업 없는 학생이다. 쉬는 학생은 뺀다. `/lessons/:id/review`도 수업 준비 탭으로 표시한다.
   - 처음에는 "준비 중 / 확정한 수업안" 두 목록과 학생을 고르는 [새 수업 준비] 버튼으로 만들었다. 같은 날 직접 써 보니 직관적이지 않았다. 선생님은 "다음에 누구 수업이 있지?"에서 출발하기 때문이다. 그래서 학생 카드 + 일정 순으로 바꿨다 (2026-10-21).
   - 수업 전체 목록 API는 만들지 않는다. 학생별 `GET /students/{id}/lessons`를 모아서 쓴다 (학생 3~10명).
   - 준비 폼은 `PrepDialog` 하나로 만들어 학생 상세와 수업 준비 탭이 같이 쓴다. `?student=<id>`로 그 학생의 준비 폼을 바로 열 수 있다.
4. **수업 준비 결과 화면 순서: 학생 요약 한 줄 → 브리핑(문법 설명 포인트·모국어별 실수·예상 질문) → 7단계 흐름 → 범주 검토.**

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| A. 메뉴 그대로, 학생 상세 안에 탭 | 학생 화면 안에 "준비 / 기록" 탭 | 학생 맥락이 끊기지 않음 | 여러 학생의 준비 상황을 한눈에 볼 곳이 없다 |
| A'. 상태별 수업 목록 (처음 구현) | "준비 중 / 확정" 두 목록 + 학생 고르는 버튼 | 상태를 한눈에 봄 | 선생님은 학생·일정에서 출발한다. 준비 안 한 학생이 목록에 보이지 않는다 |
| B. 수업 준비를 학생과 완전히 분리 | 준비 탭에서 학생 정보를 보지 않음 | 단순함 | 맞춤 설명이 핵심인데 누구를 위한 준비인지 흐려진다 → 요약 줄로 보완 |
| C. 수업 목록 API 추가 (`GET /lessons?status=`) | 백엔드에서 한 번에 조회 | 요청 수가 적음 | 학생 수가 적어 필요 없다. 마감 전 백엔드 변경을 줄인다 |
| D. 대시보드 "할 일"의 `toRecord`를 준비 탭에 재사용 | 이미 있는 API | 요청 1번 | `toRecord`는 수업일이 지난 것만 담아서 "수업 대기" 목록과 뜻이 다르다 |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 선생님 하루 흐름(수업 전 → 수업 준비 탭, 수업 후 → 학생 탭)과 메뉴가 맞는다.
- 좋은 점: 백엔드·AI 서버 변경이 없다.
- 대가: 수업 준비 탭을 열 때 학생 수만큼 요청이 나간다. 학생이 수십 명이 되면 C로 바꾼다.
- 대가: 자주 안 쓰는 페이지는 한 번 더 눌러야 한다.

## 재검토 조건
- 학생이 20명을 넘거나 준비 탭이 느려지면 → 수업 목록 API(대안 C)
- 문법 질문 챗봇을 메뉴에서 바로 열어야 한다는 의견이 나오면 → "문법 찾기" 주 메뉴 추가
