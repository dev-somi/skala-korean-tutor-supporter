# ADR-0044: 문법 근거를 태그로 못 찾으면 본문 글자로 찾고, 여러 개면 벡터 점수로 고른다
- 상태: Accepted (2026-10-22)
- 관련 모듈: `ai-server/app/rag/index.py` (`find_by_text`), `ai-server/app/agent/grammar_qa.py` (`text_pattern`, `text_excerpt`, `collect_evidence`), `frontend/src/api/types.ts` (`GrammarSource.kind = 'text'`)
- 트러블슈팅: [TS-0007](../troubleshooting/0007-eullaeya-no-evidence-despite-indexed-text.md)
- 관련 ADR: [ADR-0025](0025-form-key-tags-and-merged-editions.md) (형태 키 태그, 검색 순서 결정 4를 한 단계 늘린다), [ADR-0037](0037-listed-conjugations-and-head-form-evidence.md) (관련형 → 대표형), [기획 ADR-0036](../planning-adr/0036-ai-explanation-when-no-textbook-evidence.md) (근거 없으면 AI 설명)

## 배경 (Context)
- 2026-10-22 "-을래야 어떻게 설명해?"가 "교재 근거 없음"으로 나오고 AI가 틀린 설명을 만들었다. 그런데 색인 글에는 `-을래야`가 3군데 나온다 (4B 익힘책 지침서 16과, 4B 매뉴얼 16과, 4B 익힘책 17과).
- 못 찾은 이유:
  1. 교재는 표준어 `-(으)려야`로 가르친다 (teaches `-려야`). 표준 등급 목록에서는 `-을래야`가 따로 떨어진 항목(4급)이라 ADR-0037의 관련형 연결도 없다.
  2. OCR이 닫는 따옴표를 놓쳐(`'-을래야 로`) mentions 태그가 붙지 않았다.
  3. 의미 검색 경로는 지침서만 보고, 결과 중 그 형태가 mentions에 있는 구역만 남긴다. "-는"이 "-는데" 구역을 끌어온 문제(ADR-0025) 때문에 일부러 좁혔다.
- 96권, child 28,089개를 임베딩해 두었지만 실제로 벡터 검색을 주로 쓰는 곳은 브리핑의 문화 포인트뿐이다.

## 결정 (Decision)
1. **검색 순서에 "글자 경로"를 더한다.** 핸드북·지침서 태그(teaches)와 의미 검색(mentions 필터)으로 아무것도 못 찾았을 때만, 본문에 그 형태가 **붙임표나 여는 따옴표 바로 뒤에** 적힌 구역을 찾는다 (`-을래야`, `'을래야`). 뒤에 한글이 이어지면 다른 낱말로 본다. 책 종류는 가리지 않는다.
2. **찾은 구역이 여러 개면 벡터 점수로 고른다** (`find_by_text`). 질문 "{형태} 문법 설명"과 그 구역 child들의 최고 코사인 점수 순으로 2개. 임베딩 서버가 없으면 책 순서대로 쓴다.
3. 형태 글자: `-(으)니까` → 으니까·니까, `-아서/-어서` → 조각마다. **두 글자 미만(조사 '도')은 찾지 않는다** (너무 흔하다).
4. **인용은 찾은 자리 앞 450자부터** 자른다 (줄 단위, 700자). "말할 때 -을래야로 발음하기도 한다" 같은 덧붙임 줄 위에 본 설명(-으려야의 의미·형태·예문)이 있기 때문이다.
5. 근거 자료에 `[출처 · 본문에 '-을래야'가 나온 곳. 이 문법(또는 같은 뜻의 표준 표기)을 설명한 부분만 쓴다]`라고 적는다. 한 쪽에 문법이 여럿 있어서 다른 문법(-는 통에)을 섞지 않게 한다.
6. 응답의 근거 종류는 `kind: "text"`. 화면은 지침서 인용과 같은 모양으로 보여 준다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| 의미 검색 결과를 필터 없이 쓰기 | mentions 필터를 뺀다 | 가장 단순 | "-는"이 "-는데" 구역을 끌어온다 (ADR-0025에서 확인) |
| 다시 색인 (태그 규칙·OCR 고치기) | 따옴표 규칙을 느슨하게 하고 다시 태그 | 근본 해결 | 책마다 규칙을 다시 봐야 하고, "다른 표기로 가르침"(-으려야)은 태그로 못 푼다 |
| 표준 목록에 -을래야 → -으려야 연결 추가 | 손으로 관련형 표 | 정확 | 이런 쌍을 다 손으로 찾아야 한다. 글자 경로는 교재가 스스로 적은 연결("구어에서는 -을래야")을 쓴다 |
| 글자만 맞추고 벡터 없이 | 책 순서대로 | 임베딩 서버 불필요 | "다시피"처럼 41곳에 나오는 형태는 순서가 의미 없다. 서버가 없을 때만 이렇게 한다 |

## 결과 / 트레이드오프 (Consequences)
- 2026-10-22 로컬 확인: "-을래야 어떻게 설명해?" → 4B 익힘책 지침서 16과 117쪽, 4B 매뉴얼 16과 25쪽이 근거로 붙고, 쓰임이 "의도가 있지만 결국 할 수 없는 상황을 나타낼 때 쓴다"로 나온다 (전에는 AI가 "조건이 필요한지 물어볼 때"로 지어냈다). "-다시피"는 4B 13과·15과 본책이 잡힌다.
- 좋은 점: 이미 만들어 둔 텍스트와 벡터를 문법 질문에서도 쓴다. AI 설명(기획 ADR-0036)으로 넘어가는 경우가 줄어든다.
- 대가: 한 쪽에 여러 문법이 섞인 구역은 다른 문법 글도 인용에 들어간다. LLM에 "이 문법 부분만"이라고 알리지만 작은 모델은 섞을 수 있다 (2026-10-22 확인: 핵심 차이에 "-는 통에"가 한 번 나왔다).
- 대가: 글자 경로는 child 전체(28,089개)와 점수를 비교한다. 후보 구역의 child만 계산하지만 전체를 한 번 훑는다. 지금 규모에서는 문제없다.

## 재검토 조건
- 글자 경로로 엉뚱한 구역이 자주 잡히면 → 붙임표 뒤만 보거나, 그 구역의 teaches가 표준 목록에서 같은 뜻인지 확인한다
- 일반 채팅 질문에도 자료 근거가 필요해지면 (PRD F3-6) → 같은 `find_by_text` + `search`를 쓴다
