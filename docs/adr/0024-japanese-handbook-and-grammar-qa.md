# ADR-0024: 일본어판 핸드북 색인 + 표준 ID 필터 경로로 문법 질문에 답한다
- 상태: Accepted (2026-10-21), 결정 2(표준 ID 대응표)·3(표준 ID 필터 경로)만 Superseded by [ADR-0025](0025-form-key-tags-and-merged-editions.md) (2026-10-21)
- 관련 모듈: `ai-server/app/agent/grammar_qa.py`, `ai-server/app/rag/` (ocr, chunk, index), `ai-server/scripts/ocr_vision.swift`, `ai-server/data/standard/handbook_map.json`, `backend/.../chat/`
- 기획: [기획 ADR-0024](../planning-adr/0024-grammar-qa-chat-p0.md)
- 관련 ADR: [ADR-0013](0013-process-over-model.md), [ADR-0014](0014-teaching-material-rag.md), [ADR-0016](0016-standard-level-list-and-item-ids.md), [ADR-0022](0022-l1-notes-data.md)

## 배경 (Context)
- 기획 ADR-0024로 문법 질문(F6-4)을 P0로 올렸다. 질문은 "A랑 B 뭐가 달라?"처럼 **형태가 정해진** 경우가 많다.
- 「세종학당 한국어 회화 어휘와 문법 1·2」 일본어판(71쪽, 63쪽)은 글자 층이 없는 PDF다. 한 쪽 = 문법 항목 하나이고, 예문 + 한국어 설명 + 일본어 설명이 있다. 이미 색인한 영어판(1권)과 항목 번호가 같다.
- macOS Vision으로 ko-KR 우선 OCR하면 일본어가 깨지고, ja-JP 우선이면 한국어가 깨진다.
- 영어판 핸드북의 문법 항목 이름은 절반이 비어 있었다 ("2-1"과 형태가 다른 줄로 읽힘). 2권은 어휘/문법 구분 쪽을 못 알아봐 문법 항목이 모두 "어휘"로 분류됐다.
- ADR-0014의 재검토 조건: "다른 교재를 쓰게 되면 → 교재와 무관한 학습 항목 ID를 붙인다".

## 결정 (Decision)
1. **OCR을 두 번 하고 합친다** (`ocr.py --ja`). ko-KR 우선 결과를 기본으로, ja-JP 우선 결과에서 **히라가나가 2자 이상인 줄**만 골라 같은 자리의 줄을 바꾼다. 한국어를 일본어로 잘못 읽으면 가타카나만 섞이기 때문이다 ("가" → "フト"). 언어는 `OCR_LANGS` 환경 변수로 바이너리에 넘긴다.
2. **핸드북 항목 → 표준 문법 ID 대응표** `data/standard/handbook_map.json` (키 `시리즈/과-번호`, 예: `practical2/6-2` → `std-g-024`). 영어판·일본어판이 같은 대응을 쓴다. 자동 대응 후 Claude가 하나씩 확인했다(선생님 검수 전). 청크 때 parent에 `std_ids`를 붙인다.
3. **필터 경로 `get_grammar(std_id, lang)`** 로 핸드북 항목을 정확히 가져온다. 임베딩을 쓰지 않는다. 표준 ID당 2쪽까지(1권 기본 + 2권 확장·비교).
4. **문법 질문 흐름 (그래프 없는 함수, intake와 같은 방식)**
   1. 형태 뽑기: 질문에 적힌 형태("-아서랑", "은/는")를 코드로 표준 목록에 맞춘다. 조사가 붙으면 뒤에서 한 글자씩 뗀다. 못 찾으면 저가 모델 1회 → 다시 코드로 검증 (권위 게이트). 동음이의는 가장 낮은 등급, 그중 핸드북에 있는 항목을 우선한다.
   2. 근거: 모국어판 핸드북(필터) + 모국어 노트(`notes_for_std`) + 지침서(의미 검색. 형태가 "-형태" 모양으로 본문에 있을 때만).
   3. 등급: 표준 등급 > 학생 등급이면 `out_of_level`. 근거가 없는 형태는 `ungrounded_forms`.
   4. 요점: quality 티어 LLM 1회, 근거만 넣어 한국어 요점 2~4개. **인용 예문이 근거에 없으면 그 요점을 빼서 `removed_points`로** 돌린다 (기획 ADR-0017).
   5. 학생 모국어 설명은 LLM이 쓰지 않는다. 핸드북 원문을 보여 주고, 깨진 「」 안은 첫 번째만 항목 이름으로, 나머지는 「…」로 바꾼다.
5. **API**: ai-server `POST /grammar-qa {question, native_language, student_level}`. Spring 채팅에 `grammar_qa` 의도를 추가해 학생이 지정되면 모국어·등급을 넘기고, SSE `sources` 이벤트로 근거를, `token`으로 요점을 보낸다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| OCR 언어 하나 (ko+ja 순서만 조정) | 한 번에 읽기 | 빠르다 | 어느 순서든 한쪽 언어가 깨진다 (66쪽 시험) |
| Claude 비전으로 일본어판 OCR | 쪽 이미지를 모델에 | 「」 안 한국어까지 정확 | 134쪽 비용, 마감 전 시간. Vision 두 번 읽기로 설명 본문은 충분히 읽힌다 |
| 의미 검색만 | 질문으로 핸드북 검색 | 대응표가 필요 없다 | 형태를 이미 아는데 검색 오차를 들일 이유가 없다 (ADR-0014와 같은 판단). "-는"이 "-는데" 쪽을 끌어온다 |
| 형태 → 표준 ID 자동 매칭만 | 항목 이름을 실행 때마다 맞춤 | 대응표를 관리하지 않는다 | "-을 거예요" → 관형형 -을(2급), "-은지" → -는지(4급)처럼 틀린다. 손으로 고친 표가 필요하다 |
| 핸드북 대응을 textbook_map에 합치기 | 같은 파일 | 로더 하나 | textbook_map 키는 교재 항목 ID 형식(`u03-g02`)으로 검증된다. 성격이 다른 키를 섞지 않는다 |
| LangGraph 그래프 | 노드로 나눔 | 진행 단계를 스트리밍 | 분기·루프·HITL이 없다. 함수 하나로 충분하다 (ADR-0009) |

## 결과 / 트레이드오프 (Consequences)
- 좋은 점: 2026-10-21 로컬 qwen3:8b로 "-아서랑 -(으)니까", "-고랑 -아서", "사는이랑 살던"이 모두 쪽수 근거와 함께 답한다. "-고랑 -아서"는 2권 2-2의 직접 비교 설명을 요점에 그대로 쓴다.
- 좋은 점: 색인에 영어판 항목 이름이 모두 채워지고(28/28), 2권 문법 항목 29개가 제대로 분류됐다.
- 대가: 한 쪽을 두 번 OCR해서 시간이 두 배다 (134쪽에 약 2분).
- 대가: 일본어 설명 안의 한국어(「」)는 여전히 깨진다. 「…」로 가리고 원문 쪽을 보여 준다.
- 대가: 대응표는 검수 전이고, 새 핸드북을 넣을 때마다 손으로 만들어야 한다 (권당 약 28개).
- 대가: 지침서 근거는 의미 검색이라 엉뚱한 구역이 붙을 수 있다. 형태가 본문에 있는지로 거르지만 완벽하지 않다.

## 재검토 조건
- 「」 안 한국어가 꼭 필요하면 → 설명 상자 영역만 Claude 비전으로 다시 읽는다
- 핸드북이 더 늘면(3·4권, 영어판 2권) → 대응표 초안 스크립트를 `app/standard/`에 정식으로 둔다
- 지침서 근거가 자주 엇나가면 → 지침서 구역에도 표준 ID를 붙여 필터 경로로 바꾼다
