# ADR-0025: 교수 자료 색인 v2 — 문법은 형태 키 태그로 찾고, 언어판은 한 덩어리로 합친다
- 상태: Accepted (2026-10-21)
- 관련 모듈: `ai-server/app/rag/` (chunk, index, 새 forms), `ai-server/app/agent/grammar_qa.py`, `ai-server/app/standard/l1_notes.py`
- 기획: [기획 ADR-0025](../planning-adr/0025-material-tiers.md)
- 대체: [ADR-0024](0024-japanese-handbook-and-grammar-qa.md)의 결정 2(핸드북 → 표준 ID 대응표), 3(표준 ID 필터 경로)
- 관련 ADR: [ADR-0014](0014-teaching-material-rag.md), [ADR-0016](0016-standard-level-list-and-item-ids.md), [ADR-0022](0022-l1-notes-data.md)

## 배경 (Context)
- 지도교수 의견(2026-10-21): PDF를 모두 텍스트로 바꾸고 벡터 검색하라. 변환 비용은 처음 한 번뿐이다. 확인해 보니 OCR(macOS Vision)과 임베딩(Ollama bge-m3)은 모두 로컬이라 토큰이 들지 않는다. 134쪽 두 번 읽기에 약 2분이다.
- 그대로 다 넣었을 때의 문제는 비용이 아니라 검색 품질이다.
  1. 같은 책의 한국어·영어·일본어판이 결과를 같은 내용으로 채운다. 세 판은 **쪽 수가 같다** (한국어 1: 280/280/280, 3A: 240×3, 익힘책 1: 392×3).
  2. 짧은 문법 형태는 벡터 검색이 구분하지 못한다. 2026-10-21에 "-는"이 "-는데" 구역을, 따옴표 뒤 조사 '는'이 있는 구역을 끌어왔다.
- ADR-0024의 표준 ID 대응표는 애매하다. "-을 거예요"는 표준 목록에 맞는 항목이 없고, "-던"은 "-던-"(3급)과 "-던"(6급)으로 갈리고, 동음이의 중 하나를 골라야 하고, 핸드북마다 손으로 표를 만들어야 한다.
- 자료마다 문법 제목이 이미 적혀 있다: 핸드북 "14-1 -아서/-어서/-여서(1)", 5~6급 지침서 "‘...은 -기 나름이다’를 도입한다", 3~4급 매뉴얼 "1. -나 보다, -는가 보다", 지침서 본문 "'-어서'와 구분이 분명하다".

## 결정 (Decision)
1. **모든 1순위 자료를 텍스트로 바꿔 둔다** (기획 ADR-0025의 목록). 글자 층이 있으면 `textlayer`, 없으면 `ocr`, 한국어·일본어가 섞이면 `ocr --ja`.
2. **형태 키(form key)**: 문법 형태를 정규화한 문자열. 화면에는 보이지 않는다.
   - 어미·표현은 "-"를 붙여 조사와 구분한다: "-는"(어미) ≠ "는"(조사).
   - 이형태는 정규 키 하나로 모은다: 아/어/여 → 어, 앞의 "으" 빼기, 을/ㄹ → ㄹ, 은/ㄴ → ㄴ, 조사 쌍(이/가, 을/를 …) → 앞쪽.
   - 띄어쓰기는 "_"로 남긴다: "-는 데"(의존명사) ≠ "-는데"(어미). "(1)" 같은 번호는 지운다.
   - "A/B/C 꼬리"는 꼬리를 앞 조각에도 붙인다: "-는/-은/-ㄴ 게 어때(요)?" → {-는_게_어때요, -ㄴ_게_어때요 …} ("-는" 단독 키가 생기지 않게).
   - 예: "-아서/-어서/-여서(1)" → {-어서}, "-(으)니까" → {-니까}, "-고 싶다" → {-고_싶다}, "은/는" → {은}
3. **청크에 태그 두 종류**를 붙인다.
   - `teaches`: 그 구역이 **가르치는** 문법. 제목·도입 문장에서 뽑는다 (책 형식별 규칙).
   - `mentions`: 본문에 따옴표로 **언급된** 문법 ('-어서', ‘-기 나름이다’). 비교 설명("-어서와 구분이 분명하다")을 찾는 데 쓴다.
4. **검색 순서**: 질문의 형태 키 → `teaches`가 맞는 청크(정확 조회) → 그중 비교 대상을 `mentions`하는 청크를 앞으로 → 부족하면 같은 책·언어 필터 안에서 벡터 검색. 벡터 검색은 "어떻게 가르치나" 같은 설명 글을 찾을 때만 쓴다.
5. **언어판은 색인에서 합친다.** PDF는 합치지 않는다. 덩어리 하나 = (시리즈, 항목 또는 쪽). 검색과 임베딩은 한국어 글로 한 번만 하고, 영어·일본어 글은 `translations: {en, ja}`로 붙여 학생 모국어 쪽만 꺼낸다. 핸드북은 항목 번호로, 본책은 쪽 번호로 맞춘다.
6. **표준 등급은 덤이다.** 형태 키를 표준 목록에 자동으로 맞춰 하나로 정해지면 "표준 N급"을 보여 주고, 안 정해지면 등급 없이 둔다. 손으로 관리하는 대응표(`handbook_map.json`)는 없앤다.
7. **모국어 노트(l1_notes)도 형태 키로 찾는다.** 노트의 `form`("이/가")에서 형태 키를 만든다. `std_ids`는 등급 표시용으로만 남긴다.
8. 책 형식을 모르면 "한 쪽 = 한 덩어리"로 넣고 `mentions`만 붙인다. 형식을 확인한 책만 `teaches` 규칙을 둔다.

## 검토한 대안 (Alternatives)
| 대안 | 설명 | 장점 | 기각 이유 |
|---|---|---|---|
| 벡터 검색만 (교수 제안 그대로) | 전부 임베딩, 질문으로 검색 | 가장 단순하다 | 짧은 형태를 구분하지 못한다 (2026-10-21 확인). 언어판이 결과를 채운다 |
| 표준 ID 대응표 유지 (ADR-0024) | 책 항목 → 표준 ID | 등급·노트와 바로 이어진다 | 위 "애매하다" 4가지. 책이 늘수록 손일이 는다 |
| BM25 같은 키워드 검색 추가 | 형태소 분석 + 역색인 | 일반적인 하이브리드 | 문법 어미는 형태소 분석기가 쪼개거나 붙여서 "-아서"를 그대로 못 찾는다. 자료에 이미 제목이 있으니 태그가 더 정확하다 |
| PDF를 언어별로 합친 새 PDF | 한 파일에 세 언어 | 파일이 준다 | 색인에서 합치면 충분하다. 원본을 고칠 이유가 없다 |
| 언어판마다 따로 색인 + 언어 필터 | lang 메타데이터만 | 구현이 쉽다 | 같은 내용을 세 번 임베딩한다. 한국어 설명과 일본어 설명을 같이 보여 주려면 결국 맞춰야 한다 |

## 결과 / 트레이드오프 (Consequences)
- 2026-10-21 1순위 자료 24권 색인: parent 2,730개, child 7,486개 (OCR 약 40분, 임베딩 약 3분 반, 토큰 0).
  teaches 규칙 확인: 한국어 1·2 지침서 문법 구역 77개 중 70개, 3A~4B 매뉴얼 문법 형태 103개, 5A~6B "문형" 도입, 핸드북 1~4권 문법 항목 약 110개.
  「실용 한국어」 지침서 1~4(쪽마다 개요 표와 설명이 섞임)와 「세종한국문화」 지침서는 결정 8대로 mentions만 붙였다.
- 2026-10-21 로컬 qwen3:8b 확인: "사는이랑 살던"의 -던이 3B 매뉴얼 18과에서 근거를 찾는다 (ADR-0024 때는 "근거 없음"). "-고랑 -아서"는 2권 2-2의 직접 비교가 맨 앞에 온다. "-기 나름이다"(5급)가 5A 지침서 2과에서 나온다.
- 좋은 점: 대응표 없이 새 책을 넣을 수 있다. 책마다 `teaches` 규칙 하나만 확인하면 된다.
- 좋은 점: "A랑 B 뭐가 달라?"에서 A를 가르치며 B를 언급하는 구역(지침서 18과 "-어서와 구분", 핸드북 2권 2-2 "-고와 비교")이 먼저 나온다.
- 좋은 점: 화면에 ID가 나오지 않는다. 사용자는 교재에 적힌 형태와 "표준 N급"만 본다.
- 대가: 책 형식마다 제목 뽑기 규칙이 필요하다. OCR이 제목을 틀리면 태그가 빠진다 (예: "3-11"). 그때는 `mentions`와 벡터 검색이 보완한다.
- 대가: 표준 등급을 자동으로 못 정하는 형태는 "아직 안 배운 문법" 판정을 못 한다.
- 대가: 글자 층 PDF를 `-layout`으로 뽑으면 2단 편집의 두 단이 한 줄에 섞인다 (입문·5A 지침서에서 확인). 단 순서로 다시 뽑아야 한다.

## 재검토 조건
- 형태 키 정확 조회가 자주 비면 → 자동 대응한 표준 ID로 한 번 더 찾는다
- 교재에 없는 표현을 묻는 질문이 많으면 → 형태 키 사전을 표준 목록 전체로 넓힌다
- 청크가 수만 개를 넘으면 → ADR-0014 재검토 조건대로 벡터 DB로 옮긴다
